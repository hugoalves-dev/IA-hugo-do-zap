# Evolution fixtures

`messages-upsert-synthetic.json` is a hand-authored synthetic fixture. It is not a captured webhook and does not establish compatibility with any deployed Evolution build.

The field selection is based on the official Evolution Baileys integration source: [Evolution API `whatsapp.baileys.service.ts`](https://github.com/evolution-foundation/evolution-api/blob/main/src/api/integrations/channel/whatsapp/whatsapp.baileys.service.ts). That source is the moving `main` branch; this repository currently pins no Evolution release, commit, or image digest. The fixture therefore remains synthetic until a sanitized payload from the exact pinned release is validated.

The official source wires the `messages.upsert` handler and uses Baileys message timestamps. It declares `remoteJidAlt` and `participantAlt` as optional fields on `ExtendedIMessageKey`. The mapper takes `remoteJidAlt` only alongside a direct-chat `remoteJid`, or `participantAlt` only alongside a group `participant`; it tags the same-key pair as `EXPLICIT_ALTERNATE_JID_PAIR`. It never creates an alternate by extracting digits from a LID. These are source-level field declarations, not proof that a particular Evolution release forwards a semantically valid pair; no release is pinned here.

The mapper leaves `archived` empty when it is missing or null, and preserves an explicit Boolean without converting it. The official source's `chats.update` handler currently forwards only `remoteJid` and `instanceId`, so this fixture is not evidence of a real archive snapshot. Consumers must interpret `Optional.empty()` as UNKNOWN and fail closed: do not process archive-dependent messages until a fresh, verified state bootstrap succeeds. A Boolean in an unvalidated payload is not by itself proof of a current snapshot.

The mapper accepts only `messages.upsert` records with a nonblank `data.key.id`; it returns an empty list for unsupported kinds or missing IDs. In particular, it does not turn `chats.update.remoteJid` into an event ID. The task 4 caller must route such rejected state updates to a durable quarantine using the original envelope, without generating an ID or discarding the evidence silently. Task 4 must also keep the chat state UNKNOWN until reconciliation succeeds.
